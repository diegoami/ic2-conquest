# run-exp-gap-v050

The original Imperial Conquest 2 against the remake imperial_conquest_2 v0.5.0 (commit 37f3062): the data behind
`findings/2026-10-09-remake-v050-gap-analysis.md`. The remake is a read-only clone at /home/diego/projects/ic2-remake-v050.

- `remake_cli.sh`: runs the remake's CLI; transcripts go to `cli/`, saves to the git-ignored `artifacts/run-exp-gap-v050`. `hash_saves.sh` appends their SHA-256 to `SAVES.sha256`.
- `scripts/g1`, `scripts/g2`, `scripts/g3`, `scripts/ai`: the CLI scripts. `tools/g3_craft.py` edits a remake save to stage a situation; its recipes are in `rows_g3.md`.
- `rows_g1.md`, `rows_g2.md`, `rows_g3.md`: the inventory re-checked, written by delegated agents. `rows_ai.md`: the AI, written by this session.
- `assemble.py` → `combined_table*.md` and `combined_counts*.json`. The `.v2` files are the cited ones, after NEW-g1-2's severity was marked conditional.
- **The AI measures:** `ai_metrics.py` (→ `ai_metrics_turns.jsonl`, `ai_metrics_summary.json`), `ai_movement.py`, `ai_per_seed.py`, `ai_improved.py`, `early_captures.py`, `siege_gate_summary.py`.
- **The siege-gate probe:** `siege_probe/` (a C# probe against the v0.5.0 engine DLL; `run.sh` builds it outside the repo) → `siege_gate_s<seed>.jsonl` (End turns 11-80) and `siege_gate_early_s<seed>.jsonl` (End turns 0-10).
- `known_post_v050_issues.json`: the open `post-v0.5.0` issues at the time of the analysis.
- **Binaries:** release `run-exp-gap-v050`, one `run-exp-gap-v050-saves.tar.gz`. Its members are listed in `MANIFEST-saves.txt`, whose last line is the tarball's SHA-256.
- **Rule-6 note:** during g3, 200 intermediate saves (`g3_off2_*.sav`) were deleted after counting and then regenerated by the same script. The new transcript `cli/g3_offers200.v2.txt` is byte-identical, so nothing measured was lost.
- **A second rule-6 note** (found by research's verification at `1935df5`): `g3_cafter_debt.sav` and `g3_cafter_unity.sav` were each written twice under the same name, first by `scripts/g3/craft_debt.txt` / `craft_unity.txt`, then by `craft2_debt.txt` / `craft2_unity.txt`.
  - `hash_saves.sh` had already listed the first versions (`4875e435…`, `eca3497f…`).
  - The released files are the second runs' (`384e77e0…`, `b538d60d…`, from `cli/g3_craft2_debt.txt` and `cli/g3_craft2_unity.txt`). Their hashes are now appended to `SAVES.sha256`; the old lines are kept.
  - The first versions are lost: the staged input (`g3_c_debt.sav` / `g3_c_unity.sav`) was evidently re-crafted between the two runs, so they differ.
  - Research checked that the released files still show the V04 values. Every other name written twice was byte-identical (1,342 files re-checked).
