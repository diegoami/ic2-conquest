# run-exp-g3-original-checks

Original-side checks 1 (a-f), 2, 3, 5 and 6 of the v0.5.0 gap analysis (`../run-exp-gap-v050/rows_g3.md`, "Original-side checks needed"; issue #80); check 4 needs none. Finding: `findings/2026-10-12-g3-original-checks.md`. Template: `../run-exp-g1-original-checks/`.

- **Runner:** `g3_checks.py <case> [args]` with `g3_lib.py` (stamped unique names, OCR, L1 staging helpers incl. calendar, city/fleet/map fields and `give_cities`, memory snapshots and diffs, Balance sheet reader copied from g1). One fresh Wine process per case, fast rollingsave seed exe (patched), seed 12345, Xvfb :99. Cases: `Q1ab [variants]` (rebellion), `Q1c`, `Q1c_dead` (rebirth), `Q1d` (mercenary desertion), `Q1e` (winter famine), `Q1f <rounds> [unity]` (AI deposition), `Q2`, `Q2b <n>` (quarter pair), `Q3` (news order), `Q5 move`, `Q5 storm <pairs> <cond>` (rough sea), `Q6 <trials>` (offers from a peace-only start).
- **Logs:** `g3_checks-<case>-<stamp>.jsonl`, one JSON line per step, never overwritten. Notes: `Q1ab-...074558` and `-074808` are the two batches of rebellion cases (the second adds Ariminum, Arretium and Pisae with Gaul dead); the `news_new` fields of the first logs use an index comparison that breaks when the 40-line news buffer scrolls and the memory buffer can keep stale tail lines after a File > Open (seen in `Q1c seven_control`), so the report takes new lines from the autosave's own news list (`autosave_news-*.jsonl`, written by `autosave_news.py` from the kept autosaves; later logs also hold `autosave_news`). `Q5-...080017` is the movement test; `Q5-...081141` is an ABORTED storm attempt (fleet condition 40 is the lost-at-sea threshold, so the fleet sank at once; killed by us, kept); `Q5-...081320` is the storm run with condition 80.
- **Reading helpers:** `g3_report.py` (writes the tables the finding cites: `analysis_g3*.txt`), `summ.py` (quick look), `news_scan.py` -> `news_scan.txt` (check 3 over every save under three folders), `make_code_extract.py` -> `code_extract_g3.txt` (line-numbered extract of the cited decompiled functions, pinned SHA), `release_sync.py` (idempotent upload to the release), `versioned.py`.
- **Binaries:** saves and screenshots in release `run-exp-g3-original-checks` (git-ignored `artifacts/run-exp-g3-original-checks/`); SHA-256 in `SAVES.sha256`. Staged saves carry `staged_<tag>` in their name; staging is listed in each log's `staged` line. Every autosave of every measured round is kept (`autosaveNN_<tag>_t<turn>_AUTO<turn>.SAV`).
