
## Task under review

PR #36, battles plan `docs/proposals/battles.md` §4 **B2** (battle-block decoder), **B3** (crafted mid-battle saves) and **B4**
(one pairing end to end), read with §2, §3 and CLAUDE.md. PR #35 (§3 infrastructure, B1) is already merged; review only this

## Scope
This task protects: **the integrity of the battle dataset** the B5 sweep will be built on: decoded fields that equal the game's
own state, every number traceable to a tracked output and a released save (CLAUDE.md rules 5 and 6), measurements never
overwritten or deleted, no binary in git (rule 1), and no End turn click that is not proven to be needed.

## Blocking means (any one is enough; a blocking finding means rework, never approve)
1. A Done-when line fails, or cannot be run as written: B2 (every field named or listed unknown; grid <-> screen checked on 4 cells;
   the word +2 hypothesis tested; inferred actions labelled [D] with `unknown` when ambiguous), B3 (no-op edit byte-identical, each
   edit local, an edited save resumes and plays from the edited state, one rejected/"repaired" edit reported), B4 (HI v HI size
   one, seeds 1-3, both Computer general, row format fixed, same seed byte-identical, every End turn advance verified).
2. What this task protects can be got past. The forbidden results the code must stop, any one proven is blocking:
   - a decoded field (position, type, troops, quality, morale, grid) that differs from the game's memory or File > Save As block
     while the decoder or the finding says it is exact;
   - an inferred actor, action or target written as known in a half-round where the diff does not fix it uniquely;
   - a measured output (trials.jsonl row, log, comparison, save copy) that a re-run can overwrite or delete (rule 6), or a runner
     that rewrites history instead of appending or versioning;
   - a save, screenshot or exe added to git (rule 1), or a new file in `saves/`;
   - an End turn (battle or strategic) clicked a second time without proof that the first did nothing, or a dialog answered Yes
     automatically (the "Offer of peace" must be captured or answered No);
   - a "byte-identical" or "identical" claim that the cited comparison file does not show, or that is vacuously true (no rows
     compared);
   - a block edit that changes bytes outside the field it names (no-op edit not byte-identical).
3. Behaviour the task forbids, or behaviour nobody asked for, inside a file the task requires (e.g. strategic army positions
   edited by `stage.py`, which §3.3 forbids; driver behaviour changed by default).
4. Project-specific: a number in the finding or the PR body with no tracked output under `runs/experiments/data/` behind it
   (rule 5/6); a test that still passes with the behaviour it names deleted; a memory address or threshold stated as verified with
   no evidence; a `lab` / L1 / L2 / natural label missing or wrong on a result.

Not blocking: wording, style, and defects in code the PR did not change. File those as follow-ups.
When unsure, rate it blocking and say why. An approve with a proven bypass is the costliest mistake a review can make.
