
## Scope
This task protects the line-number citations of the findings: every script that reads the Ghidra decompile must read the one pinned copy at
`~/ic2-work/decompile/` (or an explicit override), and must refuse a different file, because a cited line of `all_app_functions.txt` is only
meaningful in that exact file. The decompile itself never enters git.

## Blocking means (any one is enough; a blocking finding means rework, never approve)
1. A script under `runs/experiments/`, `tests/` or `scripts/` still defaults to `/mnt/c/...ReTools` or `~/ic2-dump`, or keeps its own copy of
   the path instead of `harness/decompile.py`.
2. A script that cites or extracts line numbers can read a dump whose SHA-256 differs from the pin without stopping (try an override with a
   pinned basename but different content, a symlink, a different IC2_WORK).
3. Any decompile content (the dump, symbols, news log, an extract beyond what was already tracked) is added to git, or a pinned hash in the
   module disagrees with `docs/environment.md`.
4. A `findings/*.md` file or a tracked measured output (json, jsonl, log, csv, txt, tsv under `runs/experiments/data/` or `runs/<id>/`) is edited
   (CLAUDE.md rules 3 and 6).
5. An old override (`IC2_DUMP`, `IC2_SYMBOLS`, `IC2_RETOOLS`) silently stops working.
Not blocking: wording, style, and defects in code the PR did not change. File those as follow-ups.
When unsure, rate it blocking and say why.
