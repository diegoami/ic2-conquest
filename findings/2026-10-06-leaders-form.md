# The original's "Human and computer leaders" form (TPickLeaders): what it shows, accepts and writes, and where the leader names come from

**Status:** draft finding from `ic2-conquest`, awaiting promotion. For clone issue `imperial_conquest_2` #719 (the clone's New Game makes one human seat and keeps each nation's leader). Task `docs/tasks/leaders-form.md`; branch `experiment/leaders-form`; run `run-exp-leaders-form` (data `runs/experiments/data/run-exp-leaders-form/`, binaries in the release of that name, hashes in `SAVES.sha256` and `MANIFEST-*.txt`). **Wine-only**: every `[confirmed]` result is seen under Wine 9.0 with the harness build `Imperial Conquest 2 fast rollingsave seed.exe`; the desktop original is not confirmed.

**Tags.** `[derived]` = read from the decompile (the function and the line of `all_app_functions.txt` or `news_log_decomp.txt`, kept in `code_extract_leaders.txt`, whose first column is that file's line number) or from the form's resource (`dfm_TPickLeaders.txt`, the TPF0 resource of the exe, line numbers of that dump). `[confirmed]` = seen in play: the screenshot and the save (the game's own autosave at the first human turn) or, where the state has no save, the 16 nation records read from the game's memory. The two are never mixed: a row is one or the other, and a row tagged `[derived]` that a play also showed says so in its own `[confirmed]` row. Every literal is the original's, read from the resource or the decompile by `claims_audit.py` and compared byte for byte with the text here.

## Answer

1. **The form** is a fixed dialog `Human and computer leaders` (client size 460 x 430): a header row (*Nation*, *human*, *Leader's name*), **16 rows in a fixed order** (Rome, Carthage, Seleucid, Ptolemaic, Macedonia, Numidia, Gaul, Greece, Celtiberia, Illyria, Dacia, Bithynia, Galatia, Armenia, Media, Thracia; row *i* is nation *i*), each a **human tick box** and a **name box** (25 characters; OK reads at most 0x1a bytes including the NUL), and **OK** and **Cancel**. It opens **after** the 16 leaders were drawn: every tick is clear, every name box shows the drawn leader and is **greyed**. [derived, confirmed] (F01-F11, F25, F26, F27, F29, N01, D01, D03, V04)
2. **Ticking a box with the mouse** wakes its name box (enabled, focused, whole text selected); **unticking** puts the nation's stored (drawn) leader back and greys the box again. The handler is bound to the **mouse-down** event, not to the click: **the space bar ticks the box but leaves the name box greyed**, and OK then keeps the drawn name. [derived, confirmed] (H01-H04)
3. **OK never refuses and never shows a message.** For each row in order: a ticked row whose human flag was clear becomes human and takes **the text of its name box, as it is** (empty, spaces, a name another nation has, accented letters and quotes are all accepted; the box itself cuts a longer text to 25 characters); an unticked row that was a computer nation is left alone (its name box is greyed, so its name cannot be edited, and whatever it holds is ignored); an unticked row that was human (only mid-game, from New player or New nation; derived, not played) is cleared to a computer nation, gets a newly drawn leader, with its treasury and score words adjusted as O02 says (O02, O04). There is **no check, so no order of checks**: one OK with an empty name, a spaces-only name, a pair of equal names, an over-long name and an odd-character name was accepted whole. [derived, confirmed] (O01-O09, N01-N08)
4. **Ticks.** In a New Game, with 0 ticks, OK is accepted, the world stays in memory but **no turn starts**, the Save, Save As and Game menus are greyed and no autosave file is seen. With two humans, with six humans or with sixteen humans: accepted, the human flags in the save are exactly the ticked nations, and **the first human in the turn order plays first** (the order is drawn at New Game and does not depend on the ticks). [derived, confirmed] (T01-T06, V02, V03)
5. **Cancel** discards every tick and edit: in a New Game, Cancel and OK with no tick leave the same world (the 16 nation records are byte-identical; mid-game, OK with no tick would clear the humans, O02). The Escape key does what Cancel does (it discards the current form) and the Return key what OK does (it commits the current form). The previous game is already gone when the form opens (the confirmation was answered Yes), so **Cancel leaves no game**. [derived, confirmed] (C01-C06)
6. **The draw.** The leader names come from a pool in the DAT file: **12 names per nation**, 16 nations, 26 bytes each, read into memory at New Game; each New Game draws `Random(12)` for each nation **before** the form opens; **every New Game draws again** (the build's seed is reapplied from `SEED.TXT`), the form itself never draws, except OK's one branch that turns a human back into a computer nation (reachable only from the mid-game Game > New player / New nation, not played). With 5 seeds every drawn name is inside its nation's pool and the lists differ pairwise. [derived, confirmed] (W01-W09, W06, V02)
7. **What the clone has to change** is in "The clone today -> the original" (X01-X10).

## Method

- **Code.** `make_extract.py` writes `code_extract_leaders.txt`: `TPickLeaders_InitializeForm` (0x004571a8), `TPickLeaders_HumanOrComputer` (0x0045730c), `TPickLeaders_OK` (0x00457404), `TPickLeaders_Cancel` (0x00457590), their callers `TPremierForm_NewGame` (0x0045a9e0), `TPremierForm_NewPlayer` (0x0045b148), `TPremierForm_NewNation` (0x0045b198) and the helpers they call, with the dump's line number in the first column; the New Game setup `FUN_00448aa4` and the DAT loader `FUN_004481a0` come from `news_log_decomp.txt` (a second section of the extract). `dump_dfm.py` writes `dfm_TPickLeaders.txt`, the form's TPF0 resource read from the exe. `extract_dat_pool.py` writes `dat_leader_pool.tsv`, the pool read from the DAT at the offset **recomputed from the loader's reads** (`loader_offsets.py`), with the DAT's SHA-256.
- **Play.** `play_lib.py` + `scenarios.py` + `run_play.py` (the approach of `runs/experiments/refusal_texts/`; runner 3): each play starts a fresh Wine process on a private display (`:743`) and game folder (`~/ic2-work-leaders`) with `SEED.TXT` set, and reads the form **from the running game** with `win_state.c` (a read-only helper: for every child control its class, text by `WM_GETTEXT`, enabled and visible, `BM_GETCHECK`, `EM_GETLIMITTEXT`, selection and focus; no guess). **No click is at a fixed or guessed position.** Menus: a reset (Escape, Escape, then a click on a point located now whose pointer window the X server reports as the root window), then the OCR word *File*, then proof that the dropdown opened (its word *New* seen by OCR), then the OCR word *New*, then proof that the form window (X id) or the Confirm box appeared: each transition is a recorded step, retried at most twice, and a menu that never opens stops the play. Controls: each click is aimed at a control rectangle read from the form and re-read just before the click; the pointer is read back from the X server and must be where the click goes; the helper's verbatim line for the control is recorded with the click. **Every intermediate action is verified** against the running form: a tick (the check state, then the name box enabled, focused and its whole text selected, or, for an untick, greyed, unfocused and the drawn leader back, with the state and a screenshot taken right after the click), a name (focus, selection of the whole text, deletion, typing, each read back), a button (the form window gone), a key (the box that must change changes); a click that changes another row stops the run at once, a greyed or disabled control or an incomplete form stops it with nothing clicked (`test_runner.py` runs each case against a model of the form that keeps focus, selection, deletion, typing and the edit limit separately). Every click and key belongs to exactly one recorded step. The keys (Tab, space, Escape, Return, typing) are recorded with their reasons. After OK with at least one human the game's own autosave `AUTO0720.SAV` is kept; in every case the 16 nation records are read from game memory (`<tag>_after_ok_nations.bin`, hashed) and the screen is kept. Each New Game records the content of `SEED.TXT` it started from.
- **Recordings.** Every recording is kept under its unique tag (`LF_<play>_<batch>`, `plays_*.jsonl`) and all are audited. Batches b1 to b5 (runner 1) were made before the review of PR #60 and b6 (runner 2) after its first round; b7 (runner 3) was the first batch with the raw memory dumps; **b8 (runner 3 complete: the raw helper output before every step and of every edit stage, the raw nation records and globals words of every state read, the autosave files seen at every state read) is the evidence batch**: every `[confirmed]` row cites recordings of b8 only, and the earlier batches are kept and audited but not cited (their records lack fields the audit requires of evidence). The counts of recordings are in table `counts`, recomputed by the audit.
- **No save is possible** after OK with no human, after Cancel and after Escape (File > Save and Save As are greyed, `LF_P02_b8_after_ok_menu_file.png`): those plays cite the memory dump of the nation records and the screenshot instead, and the rows say so.
- **Audit.** `claims_audit.py` compares every literal, rule, count and check of the tables below with a source. **A claim is bound to its source phrase by phrase:** each number (written in digits or spelled out) and each word that says an operation or a direction (at least, at most, the larger, the smaller, the lowest, the highest, the same, different, negative, before, after, Escape, Return) lies inside a phrase quoted by a `says "..." :: check` item of its row, and that check must DERIVE the number and the operation from a source: a floor is re-derived from the code text (the constant, the field, and that the function it calls returns the larger of its arguments), a count limit from the call and the message it sends, a calc only from operands found in their source line, the pool, the resource or `state/sav.py` (a calc of bare numbers is refused), a comparison from the records. The Answer, the clone table and the facts table are bound the same way (an Answer phrase must be a phrase of a row the item cites; a clone fragment must be a verbatim piece of a rule it cites). Obligations come from the code and the recordings, not from the finding: every branch arm of the form handlers and of the functions they call must be claimed by a derived row, every statement of a range a derived row reads must be among the statements its check lists, and every required behaviour of the plays must be a passing check of a `[confirmed]` row. The plays table is bound phrase by phrase to the steps each recording verified. Recordings: every step must be a known kind and the steps of a play must equal the sequence its definition in `scenarios.py` prescribes (`play_plans.py` reads the source, not the record); every nation field and global word is decoded from the raw dumps and the form summaries and step states from the retained helper output, the recorded JSON only compared; a `[confirmed]` row must cite exactly the files its checks read, the observation of the recording they read, and a save or a memory dump. A requested `--exe` or `--dat` that does not exist fails. `test_claims_audit.py` (139 tests) shows that doctored literals, numbers, operation words, extract operations, offsets, records, dumps, hashes, steps and plays, a removed row, a removed control or a source-free check each fail it. Tracked outputs: `claims_audit_output*.txt`, `test_claims_audit_output*.txt`, `test_runner_output*.txt` (the highest version is the last run).
- **Seeds.** 12345 (the harness's usual), 111, 222, 333 and 777.

## What this does not establish

- **Wine only.** Nothing here is confirmed on the desktop original.
- **Mid-game use of the form (Game > New player, New nation).** OK's branch that turns a human back into a computer nation (O02: the new `Random(12)` draw), the opening state of a form that has humans already ticked (D04), the "already human, edit ignored" case (O04) and `FUN_00449078` are `[derived]` only; the Game menu cases were not played (out of scope in the task `docs/tasks/leaders-form.md`).
- **The `+0x440` raises** (O03: the larger of its value and 450; O02: the larger of its value and 500) are read from the code; no recorded New Game started a nation below either floor (V01), so the raise never changed a value in any play.
- **Dead nations on the form** (D04) cannot occur in a New Game.
- **The clock seed.** The harness build rereads `SEED.TXT` at each New Game; the unpatched exe seeds from the clock, so "every New Game draws again" is confirmed for the build only as "a new draw from the file's seed"; the original's clock draw was not played.
- **Characters beyond the Western ANSI set** (the original is ANSI, N06): the plays typed only Western European letters and ASCII symbols; other scripts were not tried; an uppercase accented letter typed through `xdotool` arrived lower-case in the box, which is the input tool, not the game.
- **Pasting** a text longer than the limit was not played (typing was, N02); the box limit (`EM_GETLIMITTEXT`) applies to typed and to pasted text alike by the Win32 edit control, not by game code.
- **The name in other windows** (balance sheet, relations, battle screens, news of later turns) was not searched; only the title bar and the first turn's news were.
- **Wine's rendering order** of the rows' controls differs from the form's own (the panels are listed bottom to top by Wine); the form's own order is the resource's, and the rows were matched to nations by their captions and by the names in game memory.
- **The Confirm box** (*Are you sure you want to start a new game ?*) was answered in plays P09 and P10 but its own screenshot was not kept (only its text read by OCR, with errors); its literal and its Yes / No / Cancel buttons are `[derived]` (C05).
- **The running form's tab order and initial focus** are not claimed: the first Tab presses were recorded (P01) but no row confirms them; only the resource's tab order is claimed (F31).
- **The running box's limit** (`EM_GETLIMITTEXT`) was read from the helper output (P01) but is not claimed as a `[confirmed]` row, because a limit has no state evidence of its own; the limit is claimed by the resource (F29) and by the 25 characters that N02 saved (N01, N02).
- **Free-text wording is checked by review, not by the claims audit** (the owner's decision on this PR, before its last review). The audit binds every number and every operation word (at least, at most, larger, smaller, then, before, after, same, different) of a rule, fact, Answer item and clone cell to a check that derives it from the code, the resource, the DAT, the dumps or the recordings. It does not bind the rest of the prose: a reversed verb (set or cleared, keeps or destroys, greyed or enabled), a swapped pair of nations or function roles, a scope word (per nation or shared), or a number replaced by another that is also true would pass it. The implementer's own consistent edits found such cases (listed in their hand-back on this PR); the reviews check this wording.
- **The seed build's autosave** is the game's own `AUTO0720.SAV` at the first human turn; the plays do not use the original's File > Save.
