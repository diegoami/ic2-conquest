# The original's "Human and computer leaders" form (TPickLeaders): what it shows, accepts and writes, and where the leader names come from

**Status:** draft finding from `ic2-conquest`, awaiting promotion. For clone issue `imperial_conquest_2` #719 (the clone's New Game makes one human seat and keeps each nation's leader). Task `docs/tasks/leaders-form.md`; branch `experiment/leaders-form`; run `run-exp-leaders-form` (data `runs/experiments/data/run-exp-leaders-form/`, binaries in the release of that name, hashes in `SAVES.sha256` and `MANIFEST-*.txt`). **Wine-only**: every `[confirmed]` result is seen under Wine 9.0 with the harness build `Imperial Conquest 2 fast rollingsave seed.exe`; the desktop original is not confirmed.

**Tags.** `[derived]` = read from the decompile (the function and the line of `all_app_functions.txt` or `news_log_decomp.txt`, kept in `code_extract_leaders.txt`, whose first column is that file's line number) or from the form's resource (`dfm_TPickLeaders.txt`, the TPF0 resource of the exe, line numbers of that dump). `[confirmed]` = seen in play: the screenshot and the save (the game's own autosave at the first human turn) or, where the state has no save, the 16 nation records read from the game's memory. The two are never mixed: a row is one or the other, and a row tagged `[derived]` that a play also showed says so in its own `[confirmed]` row. Every literal is the original's, read from the resource or the decompile by `claims_audit.py` and compared byte for byte with the text here.

## Answer

1. **The form** is a fixed dialog "Human and computer leaders" (460 x 430): a header row (*Nation*, *human*, *Leader's name*), **16 rows in a fixed order** (Rome, Carthage, Seleucid, Ptolemaic, Macedonia, Numidia, Gaul, Greece, Celtiberia, Illyria, Dacia, Bithynia, Galatia, Armenia, Media, Thracia; row *i* is nation *i*), each a **human tick box** and a **name box** (25 characters at most), and **OK** and **Cancel**. It opens **after** the 16 leaders were drawn: every tick is clear, every name box shows the drawn leader and is **greyed**. [derived, confirmed] (F01-F11, F25, F27, F29, D01, D03, V04)
2. **Ticking a box with the mouse** wakes its name box (enabled, focused, whole text selected); **unticking** puts the nation's stored (drawn) leader back and greys the box again. The handler is bound to the **mouse-down** event, not to the click: **the space bar ticks the box but leaves the name box greyed**, and OK then keeps the drawn name. [derived, confirmed] (H01-H04)
3. **OK never refuses and never shows a message.** For each of the 16 rows in order: a ticked row whose human flag was clear becomes human and takes **the text of its name box, as it is** (empty, spaces, a name another nation has, accented letters and quotes are all accepted; the box itself cuts a longer text to 25 characters); an unticked row is left alone (a computer nation's name box is greyed, so its name cannot be edited, and whatever it holds is ignored). There is **no check, so no order of checks**: one OK with an empty, a spaces-only, two equal, an over-long and an odd-character name was accepted whole. [derived, confirmed] (O01-O08, N01-N08)
4. **Ticks.** 0 humans: OK is accepted, the world stays in memory but **no turn starts**, the Save, Save As and Game menus are greyed and no autosave is written. 1, 2, 6 or 16 humans: accepted, the human flags in the save are exactly the ticked nations, and **the first human in the turn order plays first** (the order is drawn at New Game and does not depend on the ticks). [derived, confirmed] (T01-T06, V02, V03)
5. **Cancel** (or the Escape key) discards every tick and edit; **Return** is OK. Both leave the same world as OK with no tick. The previous game is already gone when the form opens (the confirmation was answered Yes), so **Cancel leaves no game**. [derived, confirmed] (C01-C06)
6. **The draw.** The leader names come from a pool in the DAT file: **12 names per nation**, 16 nations, 26 bytes each, read into memory at New Game; each New Game draws `Random(12)` for each nation **before** the form opens; **every New Game draws again** (the build's seed is reapplied from `SEED.TXT`), the form itself never draws, except OK's one branch that turns a human back into a computer nation (reachable only from the mid-game Game > New player / New nation, not played). With 5 seeds every drawn name is inside its nation's pool and the 16-name lists differ. [derived, confirmed] (W01-W08, V02)
7. **What the clone has to change** is in "The clone today -> the original" (X01-X10).

## Method

- **Code.** `make_extract.py` writes `code_extract_leaders.txt`: `TPickLeaders_InitializeForm` (0x004571a8), `TPickLeaders_HumanOrComputer` (0x0045730c), `TPickLeaders_OK` (0x00457404), `TPickLeaders_Cancel` (0x00457590), their callers `TPremierForm_NewGame` (0x0045a9e0), `TPremierForm_NewPlayer` (0x0045b148), `TPremierForm_NewNation` (0x0045b198) and the helpers they call, with the dump's line number in the first column; the New Game setup `FUN_00448aa4` and the DAT loader `FUN_004481a0` come from `news_log_decomp.txt` (a second section of the extract). `dump_dfm.py` writes `dfm_TPickLeaders.txt`, the form's TPF0 resource read from the exe. `extract_dat_pool.py` writes `dat_leader_pool.tsv`, the pool read from the DAT at the offset **recomputed from the loader's reads** (`loader_offsets.py`), with the DAT's SHA-256.
- **Play.** `play_lib.py` + `scenarios.py` + `run_play.py` (the approach of `runs/experiments/refusal_texts/`; runner 2): each play starts a fresh Wine process on a private display (`:743`) and game folder (`~/ic2-work-leaders`) with `SEED.TXT` set, and reads the form **from the running game** with `win_state.c` (a read-only helper: for every child control its class, text by `WM_GETTEXT`, enabled and visible, `BM_GETCHECK`, `EM_GETLIMITTEXT`, selection and focus; no guess). **No click is at a fixed or guessed position.** Menus: a reset (Escape, Escape, then a click on a point located now whose pointer window the X server reports as the root window), then the OCR word *File*, then proof that the dropdown opened (its word *New* seen by OCR), then the OCR word *New*, then proof that the form window (X id) or the Confirm box appeared: each transition is a recorded step, retried at most twice, and a menu that never opens stops the play. Controls: each click is aimed at a control rectangle read from the form and re-read just before the click; the pointer is read back from the X server and must be where the click goes; the helper's verbatim line for the control is recorded with the click. **Every intermediate action is verified** against the running form: a tick (the check state, then the name box enabled, focused and its whole text selected, or, for an untick, greyed, unfocused and the drawn leader back, with the state and a screenshot taken right after the click), a name (focus, selection of the whole text, deletion, typing, each read back), a button (the form window gone), a key (the box that must change changes); a click that changes another row stops the run at once, a greyed or disabled control or an incomplete form stops it with nothing clicked (`test_runner.py` runs each case against a model of the form that keeps focus, selection, deletion, typing and the edit limit separately). Every click and key belongs to exactly one recorded step. The keys (Tab, space, Escape, Return, typing) are recorded with their reasons. After OK with at least one human the game's own autosave `AUTO0720.SAV` is kept; in every case the 16 nation records are read from game memory (`<tag>_after_ok_nations.bin`, hashed) and the screen is kept. Each New Game records the content of `SEED.TXT` it started from.
- **Recordings.** Every recording is kept under its unique tag (`LF_<play>_<batch>`, `plays_*.jsonl`) and all are audited. Batches b1 to b5 (runner 1, 19 successful and 4 failed recordings) were made before the review of PR #60: their resets clicked the fixed point (1000, 900) and they have no pointer or step records, so they are **kept but are not evidence**. Batch b6 (runner 2) re-recorded all 15 play ids. Counts: **15 unique play ids**; **34 successful recordings** (19 of runner 1, 15 of runner 2); 4 failed recordings (kept, not cited); 38 recordings in all (table `counts`). Every `[confirmed]` row cites recordings of batch b6 only.
- **No save is possible** after OK with no human, after Cancel and after Escape (File > Save and Save As are greyed, `LF_P02_b6_after_ok_menu_file.png`): those plays cite the memory dump of the nation records and the screenshot instead, and the rows say so.
- **Audit.** `claims_audit.py` compares every literal, rule, count and check of the tables below with a source: the tracked code extract (a cited line must be read by a check of its row; the operations a rule describes, such as the maximum of `FUN_00448fd8` or the offset +0x440, are checked as sequences of the code's own text), the form resource (every object has a row and every property of it is compared), the pool table (and the DAT, with `--dat`; a requested `--exe` or `--dat` that does not exist fails), the recordings (hashes, every click's pointer and target, steps and their postconditions recomputed from the recorded states), the saves' bytes (parsed again, hashes compared with `SAVES.sha256` and the manifests) and the screenshots. Every number of a rule's prose, of the Answer and of this section must be bound to a passing check with the same spelling (a decimal to a decimal, a hexadecimal to a hexadecimal), a `[confirmed]` row must cite exactly the files its checks read (the screenshot of the form step a check reads, the save or memory dump, the screenshot taken right after a tick), the claims the plays make must be in the finding, and every statement about all recorded games is a row of the facts table recomputed from the records. `test_claims_audit.py` (88 tests) shows that a doctored literal, prose number, extract operation, offset, save, screenshot, record, seed or count, a removed control, a removed claim, a swapped screenshot and a missing requested source each fail it. Tracked outputs: `claims_audit_output*.txt`, `test_claims_audit_output*.txt`, `test_runner_output*.txt` (the highest version is the last run).
- **Seeds.** 12345 (the harness's usual), 111, 222, 333 and 777.

## What this does not establish

- **Wine only.** Nothing here is confirmed on the desktop original.
- **Mid-game use of the form (Game > New player, New nation).** OK's branch that turns a human back into a computer nation (O02: the new `Random(12)` draw), the opening state of a form that has humans already ticked (D04), the "already human, edit ignored" case (O04) and `FUN_00449078` are `[derived]` only; the Game menu cases were not played (out of scope G02-G04, task `docs/tasks/leaders-form.md`).
- **The `+0x440` raises** (the larger of the word and 450, and of the word and 500) are read from the code; no recorded New Game started a nation below either floor (V01), so the raise never changed a value in any play.
- **Dead nations on the form** (D04) cannot occur in a New Game.
- **The clock seed.** The harness build rereads `SEED.TXT` at each New Game; the unpatched exe seeds from the clock, so "every New Game draws again" is confirmed for the build only as "a new draw from the file's seed"; the original's clock draw was not played.
- **Characters beyond the Western ANSI set** (the original is ANSI, N06): the plays typed only Western European letters and ASCII symbols; other scripts were not tried; an uppercase accented letter typed through `xdotool` arrived lower-case in the box, which is the input tool, not the game.
- **Pasting** a text longer than the limit was not played (typing was, N01, F30); the box limit (`EM_GETLIMITTEXT`) applies to both by the Win32 edit control, not by game code.
- **The name in other windows** (balance sheet, relations, battle screens, news of later turns) was not searched; only the title bar and the first turn's news were.
- **Wine's rendering order** of the rows' controls differs from the form's own (the panels are listed bottom to top by Wine); the form's own order is the resource's, and the rows were matched to nations by their captions and by the names in game memory.
- **The Confirm box** (*Are you sure you want to start a new game ?*) was answered in plays P09 and P10 but its own screenshot was not kept (only its text read by OCR, with errors); its literal and its Yes / No / Cancel buttons are `[derived]` (C05).
- **Tab order beyond the first eight presses** was not walked in play: the order of the later rows is the resource's (F31).
- **The seed build's autosave** is the game's own `AUTO0720.SAV` at the first human turn; the plays do not use the original's File > Save.
