## What does not match — three open notes

1. **F02's "names of computer nations are greyed"** is a runtime colour-state, not in TPF0. The `pnl_<nation>` rows carry no `Font.Color` setting in the extract; the runtime `OnMouseDown=HumanOrComputer` toggle on `cbx_<nation>` is what flips the grey. Reproducing the visual needs the form's runtime: on click of `cbx_<computer>`, set its `ed_<computer>.Font.Color := clGrayText` (or equivalent). **Recorded as a reproduction deliverable** for the clone's TPickLeaders analog, not as a missing verification.
2. **F04's "no backup"** is a single-`fopen` behaviour inside `SaveGameFile`; the function reads the save path, overwrites it, and returns. The path of *no* `.bak` rename and *no* "are you sure" is not in the literals table — would need capstone on `SaveGameFile`.
3. **F02's "Several humans can be ticked"** is a multi-select state, not directly visible in the TPF0: each row's `cbx_<nation>` is independent, so up to 16 humans can be checked. The harness reproduced this with `T0_NEWGAME_AUTO0720.SAV` (humans 1 and 3). Carrying the multi-check live evidence is enough; a clone reproducing the F02 dialog just needs each checkbox to be independent + the OK handler reads them all.

## Method

- **Form + function + literal extraction.** `runs/experiments/feature_inventory/extract_forms.py` (form controls) + `extract_dump_strings.py` (function list + literals).
- **Reproduction row.** Two controlled saves `NEW_a.SAV` and `NEW_b.SAV` collapse to one byte-stream (`050bc354…`) and equal `BASE.SAV` — i.e. `File>New` with the same seed gives the same starting state (per `findings/2026-09-29-loading-a-save-does-not-reseed.md`'s sibling finding).
- **Multi-human live evidence.** `findings/2026-10-02-two-human-seats.md` — Rome and Carthage ticked, `T0_NEWGAME_AUTO0720.SAV` saved. The 16-nation panel order is preserved across the form extraction (Rome=0 ... Thracia=15), matching `state/sav.py` `NATIONS`.
- **Tag scheme.** Same as the other drafts: `[confirmed]` when a tracked file lists the cited evidence.

## Inferences

- **F01/F03/F04/F05/F06 form a stack that routes all through one shape**: the menu item calls `OnClick`, the form's `OnClick` calls a named method in the same class, the method either asks for confirmation (`NewGame`, `CheckQuit`) or routes to file I/O (`OpenGameFile`, `SaveGameFile`, `SaveGameFileAs`). The shape is identical across the five rows; per-row verifications differ only by literal text (`Are you sure you want to ... ?`).
- **F02 is a fully separate form** (`TPickLeaders`) called from `TPremierForm_NewGame`'s Yes. It has 16 nation panels, each a self-contained sub-form (panel + checkbox + edit). The cleanest reproduction pattern is: 16 panels under one form, OK walks the `cbx_<n>.Checked` to set the seat mask, then writes the leader-name string list. The TPF0 structure already encodes that nesting.

- F04's no-backup behaviour (above).
- The exact text of F03's file dialog when invoked (Delphi's standard `TOpenDialog`; not a custom form).
