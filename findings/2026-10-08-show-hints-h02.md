**Status:** draft from `ic2-conquest`, awaiting promotion. Companion to `findings/2026-10-05-player-facing-feature-inventory.md` row H02. Independent of issue #722 (H02 is a UI toggle, not a missing help page); the row is included here because the existing feature inventory groups all "Help" rows together.

**Tag:** `[confirmed]` (carried from the feature inventory; this draft tightens the cell-level form/menu extraction).

## Answer

The H02 row is fully backed by tracked data — the menu item, the handler, and three screenshot states that prove the on / off / on cycle.

| Sub-claim | Source | Match status |
|---|---|---|
| The Help menu has a **Show hints** toggle (ticked by default) | `runs/experiments/data/run-exp-feature-inventory/form_controls.tsv` row `TPremierForm/PremierForm/MainMenu/mt_Help/mn_Showhints`: `class=TMenuItem`, `caption="Show hints"`, `OnClick=ToggleHints`, **`Checked=True`** (the column header is `checked`) | identical |
| Clicking it flips the toggle | `function_list.tsv` row `TPremierForm_ToggleHints @ 0x0045c294` | identical |
| The hint is the **speed-button hint** under the pointer | the toggle flips the application's `ShowHint` plus the item's `Checked` plus a per-nation flag byte (per the feature inventory's row prose); the screen-capture in explore `runs/experiments/feature_inventory/explore_b2.py` records the visible diff: hint `"Rome"` shown on the speed button under the pointer when on, not shown when off | identical |
| Ticked by default and the cycle is on → off → on | The three screenshots `FI_b2_03_hint_on_before.png`, `FI_b2_03_hint_after_toggle.png`, `FI_b2_03_hint_on_again.png` (release asset `FI_batch2_screenshots.tar.gz`, hashed in `MANIFEST-batch2.txt`). The **before** and **on_again** screenshots have SHA-256 `0f71581febb85ea32bd2ae03420fd47b94082529e7d53af7952b6db55138fea8` — **byte-identical**, confirming the cycle returns to the initial state exactly. | identical |

## What does not match — one open note

1. **The per-nation flag byte's meaning is not located.** The feature inventory's row prose notes that `TPremierForm_ToggleHints` "flips the application's `ShowHint`, the item's check and one per-nation flag byte (its meaning is not known)." This is **out of scope** for the H02 verification — the toggle's observed behaviour (the screenshot cycle) is captured; the meaning of the unknown byte is independent of the H02 row. Recorded only so it isn't lost: the byte is in the nation record and the decompile will be reopened when something reads it.

## Method

- **Form + function extraction.** Same toolchain as `2026-10-08-help-topics-h01.md` and `2026-10-08-cellular-automata-easter-egg-h04.md`. `form_controls.tsv` holds the `mn_Showhints` row with `Checked=True`; `function_list.tsv` holds the named handler.
- **State-cycle evidence.** The three batch-2 screenshots record the on / off / on states; the **byte-identical hash** of `FI_b2_03_hint_on_before.png` and `FI_b2_03_hint_on_again.png` is the strongest single observation: a one-shot screenshot capture and a re-toggle + recapture produce the same pixels, modulo no race condition.
- **Tag scheme.** Same as the other Help rows: `[confirmed]` when a tracked file lists the cited evidence; this draft tightens the cell-level extraction.

## Inferences

- The toggle's default value (`Checked=True` from the Delphi form resource) is also the runtime default — the saved form opens with hints ticked on. A clone's `ShowHints` analogue should follow the form resource's `Checked` rather than a hard-coded `True`.
- The form resource and the runtime are consistent, so the screen-shot capture and a fresh Wine run produce the same starting state. This is the only Help-row whose cycle evidence is byte-identical end-to-end (helpful for a future regression test).

## What this does not establish

- The meaning of the per-nation flag byte (`feature_inventory/2026-10-05-player-facing-feature-inventory.md` row H02 prose).
- Whether hints are *also* rendered by anything beyond Delphi `ShowHint` (e.g., a custom-drawn label under the speed button). The `OnClick=ToggleHints` handler alone flips the application's standard `ShowHint`, but the decompile will need a re-read to confirm there isn't a parallel hint custom-draw.
